The basics of git (branch, commit, rebase, revert) get you through a normal
week. The weeks that go wrong look different: a fix that has to reach a
release branch without the six features merged since, a branch built on
another branch that was squash-merged, a rebase that stops on a lockfile,
a merge that has to come out of `main` at 5 pm and go back in on Monday,
an API key pushed to a public PR.

Each question is one of those weeks. They all have a command that "works"
and leaves a mess for the next person, and a command that fixes the problem
and leaves the history honest. Some questions have more than one correct
answer.
