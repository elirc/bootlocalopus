Knowing a pattern is the easy half. The half that shows up in code review is
**when**: when a pattern removes a real problem, when it is ceremony that
makes a three-line `if` into four files, and which failure modes each one
brings with it (observers that leak, undo for things that cannot be undone,
dependencies injected "for flexibility" that nothing ever varies).

These questions are the judgement calls from the lessons in this chapter.
Some have more than one right answer.
